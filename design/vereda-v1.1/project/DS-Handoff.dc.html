Vereda design system · Developer handoff

Tokens, component specs & accessibility contract

Tokens follow the three-tier model from the Isla Abierta spec (global → alias → component) and the white-label theming engine in the technical specification §10.1: everything below is a CSS variable or a JSON value a tenant config can override, never a hard-coded hex in a component.

03 · Accessibility contract · WCAG 2.2 AA

What every PR is checked against

Perceivable

  • Text 4.5:1, large text and UI parts 3:1; tokens pre-validated (sheet 01 figures).
  • Every image has alt copy written by content, not auto-generated; decorative images alt="".
  • Body never below 16 px; layouts survive 200 % zoom and 320 px width.
  • Status = icon + label + colour; charts in admin add patterns or labels.
  • Video captioned; no autoplay with sound.

Operable

  • Skip-to-content is the first focusable element.
  • Focus ring 2 px primary-500 (teal) with 2 px offset on light surfaces, accent-500 (ochre) on dark ones; never removed; 3:1 against adjacent colours (ochre on cream measured 1.78:1, hence the change on 6 Oct).
  • Touch targets ≥ 44 px (48 px baseline), 8 px apart.
  • No time limits on sessions during booking; the 48 h payment window is a business deadline, not a UI timer that logs you out.
  • Drag (map, gallery) always has a button alternative.

Understandable

  • lang per page and per switched passage (Spanish host names inside English copy don't need it; a Spanish paragraph does).
  • Error summary at the top of long forms, linked to fields; errors stay until fixed.
  • Consistent nav order across pages; the same label means the same thing in traveler and admin UI.
  • Legal pages open with a plain-language summary.

Robust & tested

  • Semantic HTML first; ARIA only where native falls short (listbox menu, tabs, dialog).
  • axe in CI, Lighthouse accessibility ≥ 95 as a release gate.
  • Screen-reader pass per flow with VoiceOver (iOS), TalkBack (Android), NVDA; in English and Spanish.
  • Accessibility statement (EN/ES) in the footer with known issues and a contact.

04 · Interaction & content notes

Rules that are easy to lose in a sprint

Booking model & price

  • The model badge (Instant / Request · 24 h) appears on the card, the detail hero and the review step. Never first revealed at payment.
  • Displayed price always includes mandatory fees; optional extras itemised; processing fee shown per method.
  • Prices round up to the whole unit; rate locked at deposit; show "Prices set in EUR" when another currency is displayed.
  • "Confirming availability…" never reads "Booked" until the gateway and supplier both answer.

Low bandwidth

  • Initial page < 1 MB, < 3 s on 3G; hero ≤ 100 KB, thumbnails ≤ 20–40 KB, AVIF/WebP with JPEG fallback, srcset.
  • Text and prices render server-side before any script.
  • Text-only mode auto-prompted under 200 kbps; "Load photo · size" buttons.
  • Offline kit: IndexedDB, read-only; writes queue with a visible "will send when online".

Localisation

  • Strings live in /locales/{lang}.json; no copy in components (spec §10.3).
  • Dates per locale; ISO stored. Numbers: 1,234.56 € (EN), 1.234,56 € (ES/FR/DE).
  • Neutral Latin-American Spanish; Quebec French for CA; German Sie in booking, du in blog.
  • Cuban terms (casa particular, paladar, almendrón, guagua) keep the Spanish word with a one-line gloss on first use.
  • Banned phrases enforced in content review: "the real Cuba", "off the beaten path", "hidden gem", "before it changes", "gritty", "raw".
