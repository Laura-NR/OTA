Triggers, subjects, plain text, SMS budgets

The ten emails and the phone board on this page show the rendered templates. This sheet is the table behind them: what fires each one, in which language, with which subject and attachments, the plain-text body a text-only client receives, and the character and segment budget of every SMS and push, so the copy survives a 2G connection in Viñales.

01 · Sender and identity

  • Email from Vereda Expeditions <desk@vereda.travel>; replies land in the desk inbox on the booking thread (A-Booking › Messages). Workers: colaboradores@vereda.travel, Spanish.
  • SMS sender "Vereda" (alphanumeric; numeric fallback where the carrier requires one, e.g. US). Short links are signed: vereda.travel/pay/7K2M9Q.
  • Push: title ≤ 40 characters, body ≤ 90; tapping opens the exact screen (deep link), never the home screen.
  • Every email carries the MINTUR licence line and the 24/7 number in the footer; transactional emails have no unsubscribe link (contract necessity); only the monthly "Cuba right now" is marketing and has one.

Language, time, quiet hours

  • Traveler messages in the traveler's locale (users.locale: EN, ES, FR) from one template; DE / IT travelers receive EN until those locales exist.
  • Deadlines are stated in Havana time and the traveler's local time: "14:35 Havana (20:35 Berlin)". Dates per locale (T-Forms 00).
  • Quiet hours: no non-critical SMS or push between 22:00 and 08:00 in the traveler's local time; the morning check-in is 08:30 Havana by design. Critical advisories and disruption options ignore quiet hours.
  • Worker messages always Spanish; the sign-in code and offer SMS are sent any hour the worker is marked available.

Retries, fallbacks, dedupe

  • Email hard bounce → the same content as SMS (short form) + a desk task; SMS failure on a payment or critical message → the desk calls (A-Dashboard › On the ground).
  • Worker offer: push at T+0, SMS at T+60 min if unseen, desk call at amber (75 %), fallback re-dispatch at red (G-Dispatch).
  • Each send has an idempotency key booking_code + template + occurrence: a retried job never sends twice.
  • Everything sent is logged on the booking's communication history (A-Customers) with channel, language and delivery status.

04 · SMS budget · as drawn on S-Messages

GSM-7 gives 160 characters per message (153 when concatenated); one character outside the GSM-7 set switches the whole message to UCS-2 with 70 per segment. In Spanish, á í ó ú are outside the set, é è ñ ü à are inside, and € counts as two. SMS copy therefore drops the accents on á í ó ú only (never in email or the apps).

06 · Localisation limits

  • Subjects ≤ 60 characters in EN; ES and FR may run to 72. The booking code goes last so it survives truncation on phones.
  • Preheaders ≤ 90 characters; never repeat the subject.
  • Money: "€ 620.00" in EN, "620,00 €" in ES and FR; SMS uses "€ 620" (no decimals) in every language.
  • Names: first name only, as typed by the traveler; workers by first name in traveler messages (spec §8.2).
  • Strings live in the i18n catalogue with the template id as key prefix (email.invoice.subject), per spec §10.3.
