05 · How a change is made from here

  1. Ask on the canvas: a sticky note beside the artboard (red = blocks a build, orange = should fix, blue = question, gray = cosmetic, green = keep) or a comment thread on the frame. Usability findings use the same colours (T-Testing).
  2. Triage weekly with the dev lead: accept, defer or decline; declined notes are kept, marked.
  3. Change the artboard, then publish with a version label v1.x · dd Mon · artboard · what. Minor (x) = copy, values, states; a new major = a flow or token change, re-accepted by Vereda.
  4. Record it here (04) and on T-Matrix if a requirement's status moves; a token change also updates DS 06.
  5. Pin: tickets reference the artboard name and the version label, never "the latest".
